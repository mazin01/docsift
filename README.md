# docsift

**Turn PDFs, CSVs and spreadsheets into compact, correct, LLM-ready context. Built for Arabic and English documents.**

Feeding documents to an LLM usually means one of two bad options:

- **Dump the extracted text.** Tables lose their structure, borderless tables vanish, and Arabic comes out *backwards*. PDF extractors return characters in visual order, so `المبلغ` arrives as `غلبملا`.
- **Send every row as JSON.** It's correct, but repeating every key on every row roughly doubles the token count.

docsift reads the document locally, rebuilds tables (ruled or borderless, across pages, RTL or LTR), puts Arabic back into reading order, and renders a short **context**: a profile of each column (type, range, sum, examples) plus a few sample rows. All rows stay available as Python objects, a DataFrame or Parquet.

```python
import docsift

doc = docsift.read("orders.pdf")
print(doc.render())               # profile + 5 sample rows per table (markdown)
doc.render("tsv", rows=None)      # every row, in the cheapest format
doc.render(max_tokens=500)        # fit a budget: trims rows, then text
doc.tables[0].to_pandas(typed=True)
doc.stats, doc.warnings           # what happened, and what to worry about
```

The model gets the shape of the data and its totals up front, then asks for specific rows (or runs code over `doc.tables`) instead of reading every row.

## Install

```bash
pip install "docsift[tokens] @ git+https://github.com/mazin01/docsift"
```

Core dependencies: `pdfplumber`, `openpyxl`, `xlrd`, and [`nuqta`](https://github.com/mazin01/nuqta) (Arabic text helpers, standard library only). Extras: `tokens` (exact token counts via `tiktoken`) and `pandas` (`to_pandas`/`to_parquet`).

## CLI

```bash
docsift report.pdf                           # markdown context
docsift report.pdf --format tsv --rows all
docsift report.pdf --max-tokens 800 --pages 1-3 --stats
```

`--stats` prints extraction stats plus a token report to stderr. Errors come out as JSON with a stable code, and the exit status is 2.

## Benchmark

Six synthetic fixtures (generated by [`fixtures/generate.py`](fixtures/generate.py); ground truth CSVs alongside). The baseline is plain pdfplumber (`extract_text()` + `extract_tables()`, multi-page tables stitched).

**Cell accuracy** (header included, exact match after Unicode/digit normalization):

| fixture | pages | cells | pdfplumber | docsift |
|---|---:|---:|---:|---:|
| borderless_en.pdf | 1 | 80 | 0% | 100% |
| order_mixed.pdf (AR/EN) | 1 | 24 | 62% | 100% |
| multipage_en.pdf | 4 | 455 | 100% | 100% |
| ruled_ar.pdf | 1 | 65 | 0% | 100% |
| ruled_en.pdf | 1 | 65 | 100% | 100% |
| visual_order_ar.pdf (shaped glyphs) | 1 | 45 | 0% | 100% |

pdfplumber scores 0% on Arabic because every cell comes out reversed and the columns are read left-to-right. It also finds no borderless table at all.

**Tokens** (`tiktoken` o200k_base; other tokenizers differ, the ratios roughly hold):

| fixture | raw text | JSON records | markdown, all rows | TSV, all rows | default context |
|---|---:|---:|---:|---:|---:|
| borderless_en.pdf | 322 | 639 | 465 | 397 | 314 |
| order_mixed.pdf | 225 | 235 | 246 | 221 | 350 |
| multipage_en.pdf | 1868 | 3823 | 2445 | 2077 | 313 |
| ruled_ar.pdf | 355 | 650 | 433 | 388 | 342 |
| ruled_en.pdf | 265 | 505 | 388 | 332 | 324 |
| visual_order_ar.pdf | 374 | 416 | 283 | 252 | 319 |

Reading the numbers honestly:

- **TSV is the cheapest lossless format**, about 40% fewer tokens than JSON records and about 14% fewer than markdown (3,667 vs 6,268 vs 4,260 across all fixtures).
- **The default context pays off on real tables.** On the 90-row register it costs 313 tokens, against 3,823 for JSON (12× less) and 1,868 for the raw text dump. Its size depends on the number of columns, not rows.
- **On tiny documents it costs more than raw text.** The one-page purchase order needs 350 tokens versus 225, because the column profile is overhead when there are only 5 rows. Use `rows=None, profile=False` there. Either way the raw text is the version with the Arabic reversed.

Reproduce with `python bench/run.py`.

### Tested on real documents

The fixtures are synthetic. docsift was also checked by hand against public Arabic PDFs made with Adobe InDesign: a regulator's public guide, a 346-page bilingual national statistical yearbook, and a UN regional report. Those files aren't redistributed here. Each one exposed a quirk that the fixtures didn't have, and each is now handled and covered by a unit test:

| Real-world quirk | Symptom | Fix |
|---|---|---|
| Ligature glyphs mapped to 2+ letters (`لم`, `لا`, `في`) | `املركز` instead of `المركز` | multi-letter glyphs are pre-flipped before reordering |
| Ligature spelled as a wide glyph + zero-width parts | `محافظ يت` | zero-width parts are folded into the host glyph |
| Diacritics narrower than their letter | `مف ّصلة`, `ُيعزى` | marks get their letter's box; reordering keeps letter + marks together |
| Brackets stored as typed, not as displayed | `)موجوداتها(` | per line, take the bracket reading that balances (`nuqta`, `mirror="auto"`) |
| Rotated running titles in the margin | reversed `kooB raeY lacitsitatS` on every page | a minority of rotated text on a page is dropped as decoration |
| Decorative boxes | empty "tables" | ruled tables need at least one data cell |
| Multi-row headers with merged group labels | `col_1 … col_13` | number-free leading rows become `Group / Sub-column` names |
| Data rows without vertical rules | `16,642 0 38 0 …` in one cell | numbers are spread over the empty cells beside them, only on an exact count match |

## How it works

**Local PDF backend** (default, no network):

0. **Glyph cleanup:** ligature and diacritic fixes from the table above, and rotated margin text dropped.
1. **Ruled tables** come from pdfplumber's line and rectangle detection.
2. **Borderless tables** come from what's left of the page. Words are grouped into phrases, and lines with 3 or more phrases form a table block. Column boundaries are the x ranges that no phrase crosses, which works the same for left-, right- and RTL-aligned columns. A left-aligned header over right-aligned numbers is merged back into one column.
3. **Headers:** up to 3 leading rows without numbers form the header when there's numeric data below. Merged group labels are carried over their sub-columns.
4. **Multi-page tables** are joined when the next page repeats the header. They're also joined when a same-width table is the last on one page and the first on the next, with no repeated header.
5. **Reading order:** each cell and line goes through [`nuqta.visual_to_logical`](https://github.com/mazin01/nuqta#how-visual_to_logical-works) using the document's direction (majority of letters, or `direction=`). RTL tables get their column order reversed. Shaped presentation-form glyphs are NFKC-folded back into letters.
6. **Narrative text** is everything outside the tables. Running headers and footers (lines repeated on half the pages or more) are kept once.

**Optional LLM backend:** pass any callable `llm(pdf_bytes, prompt) -> str`. The model is asked for markdown plus fenced TSV blocks (`` ```tsv table=<name> page_start=<n> page_end=<n> ``), which keeps its *output* tokens low and parses reliably even with prose around the blocks. If nothing parses, docsift retries once with a stricter prompt. The core has no SDK dependency.

```python
import base64
import anthropic

client = anthropic.Anthropic()

def claude(pdf: bytes, prompt: str) -> str:
    with client.beta.messages.stream(
        model="claude-opus-5-5",
        max_tokens=64000,
        betas=["server-side-fallback-2026-07-01"],
        fallbacks="default",  # if a safety classifier declines, the API retries on another model
        messages=[{"role": "user", "content": [
            {"type": "document", "source": {"type": "base64", "media_type": "application/pdf",
                                            "data": base64.standard_b64encode(pdf).decode()}},
            {"type": "text", "text": prompt},
        ]}],
    ) as stream:
        msg = stream.get_final_message()
    if msg.stop_reason == "refusal":
        raise RuntimeError("model declined the document")
    return "".join(b.text for b in msg.content if b.type == "text")

doc = docsift.read("scan-heavy.pdf", llm=claude)
```

```python
from google import genai
from google.genai import types

client = genai.Client()

def gemini(pdf: bytes, prompt: str) -> str:
    resp = client.models.generate_content(
        model="gemini-2.5-flash",  # use a current Gemini model
        contents=[types.Part.from_bytes(data=pdf, mime_type="application/pdf"), prompt],
    )
    return resp.text
```

Provider limits on PDF size and page count apply, and splitting large files is up to you.

## Column profile

Each column gets a `type`: `number` (≥85% of values parse, including Arabic-Indic digits, `١٬٢٥٠٫٥٠`, `(1,250.00)` negatives), `date` (ISO or day-first, ≥75%), `date_hijri` (detected, not converted), `boolean` (`yes/no/true/false/نعم/لا`), `text` or `empty`. Each also gets null and unique counts, min/max/sum for numbers, min/max for dates, and up to 3 examples. Cells are never rewritten: profiling reads them, and `to_pandas(typed=True)` converts on request.

## Warnings and errors

| code | kind | meaning |
|---|---|---|
| `SCANNED_PDF` | error | no text layer at all: OCR first (or use the LLM backend) |
| `SCANNED_PAGES` | warning | some pages are image-only |
| `BROKEN_FONT_MAPPING` | warning | glyphs with no Unicode mapping (pdfminer's `(cid:N)`); shown as `�`, so re-export with embedded Unicode fonts |
| `INVALID_PAGE_RANGE` | error | bad `pages=` |
| `ENCRYPTED_PDF` / `UNREADABLE_PDF` | error | can't open the file |
| `LLM_EXTRACTION_FAILED` | error | your `llm` callable failed or returned nothing parseable, twice |
| `UNSUPPORTED_FILE` / `FILE_NOT_FOUND` / `EMPTY_FILE` | error | |

Errors are `docsift.DocsiftError` with `.code` and `.details`.

**CSV/Excel:** encoding detection (UTF-8/16, Windows-1256), delimiter sniffing (`,` `;` tab `|`), invisible-character cleanup in headers, title rows skipped, merged two-row headers folded (`Q1` over `Debit | Credit` → `Q1 Debit`, `Q1 Credit`).

## Limits

- No OCR. Image-only pages are reported, not read.
- The borderless detector needs 3 or more columns and 3 or more lines, with columns separated by roughly a word-height of whitespace. Dense layouts can merge columns.
- Headerless multi-page continuation is a heuristic: two different same-width tables split by a page break get merged (pass `pages=` to separate them).
- Document direction is one value per document, so a mostly-English PDF containing an Arabic-only table reads that table LTR. Pass `direction=`.
- docsift reports what the PDF's text layer says. When a font maps a glyph to the wrong character (one real report adds stray shaddas), or leaves kashida glyphs unmapped (`�`, flagged by `BROKEN_FONT_MAPPING`), copy-pasting from a PDF viewer gives the same text.
- Header detection stops at the first row containing a number, so a header row of years (`2023 | 2024`) under a group label isn't merged into the column names.
- Everything is held in memory, which is fine for documents and slow for million-row CSVs.

## Use cases

- RAG and agent pipelines that ingest reports, forms, catalogues and price lists.
- Back-office tools that need tables out of PDFs: orders, inventories, schedules, survey results.
- Arabic and bilingual (AR/EN) document processing in the Gulf and the wider MENA region.
- Cutting LLM cost by sending a profile and samples instead of whole tables.
